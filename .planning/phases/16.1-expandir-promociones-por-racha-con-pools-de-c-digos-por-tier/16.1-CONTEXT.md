# Context: Phase 16.1

**Phase:** 16.1 — Expandir promociones por racha con pools de códigos por tier
**Created:** 2026-05-08
**Domain:** Promociones / Gamificación — sistema de códigos de descuento por racha de trivia

## Domain

Sistema de códigos de descuento para trivia que extiende el existente `TriviaPromotionConfig` + `DiscountCode`. Se agregan pools de códigos por tier con límites independientes. Cada tier de streak tiene su propio pool de códigos finito. Un usuario que completa un tier recibe un código solo si ese tier tiene disponibilidad.

**Contexto existente (NO modificar):**
- `TriviaPromotionConfig` — configuración de promoción por racha (`discount_tiers` JSON ya existe)
- `DiscountCode` — códigos emitidos linked a `config_id`
- `trivia_discount_service.py` — valida `discount_tiers` JSON, `generate_tiered_discount_code()` verifica `config.max_codes - config.codes_claimed`

**Relación con Phase 16 (padre):**
- Phase 16 implementa trivia libre vs promo con protección comprable
- Phase 16.1 implementa pools de códigos por tier para las promociones de trivia existentes
- Phase 16.1 no afecta trivia libre ni el sistema de protección

## Decisions

### Pool Structure

- **Cada tier tiene su propio max_codes:** El campo `discount_tiers` JSON se extiende in-place para incluir `max_codes` por cada tier.
- **Estructura JSON extendida:**
  ```json
  [
    {"streak": 5, "discount": 50, "max_codes": 10},
    {"streak": 10, "discount": 75, "max_codes": 5},
    {"streak": 15, "discount": 100, "max_codes": 2}
  ]
  ```
- **Validación:** `validate_discount_tiers()` se extiende para validar que `max_codes` (opcional, default=∞) sea entero >= 0.

### Code Selection and Depletion

- **Solo el nivel más alto alcanzado:** Cuando un usuario completa múltiples tiers (ej: racha=15 con niveles en 5, 10, 15), recibe SOLO el código del tier más alto que alcanzó.
- **Verificación:** Se verifica solo el pool del tier más alto alcanzado. Si está agotado, no recibe código pero mantiene la racha para continuar.
- **Notificación obligatoria:** Cuando un tier se agota, se muestra mensaje informativo al usuario ("Este nivel de descuento está agotado, pero su racha continúa"). El usuario puede continuar jugando.
- **Silent skip en generación:** Si `generate_tiered_discount_code()` detecta pool agotado, retorna `None` pero NO falla el flujo de trivia. El handler decide si mostrar la notificación.

### Pool vs Individual Code Expiry

- **Expiración individual de códigos:** Cada código tiene su propia fecha de expiración basada en `generated_at + expiry_days` de la promoción.
- **Agotamiento del pool NO termina la promoción:** Si un pool se agota, la promoción continúa — solo ese tier no genera más códigos.
- **El pool solo controla cuántos se emitieron:** Se lleva conteo por tier (`codes_issued` por tier) para verificar disponibilidad.

### discount_tiers Extension Pattern

- **Extender `discount_tiers` JSON in-place:** No crear columna separada ni tabla nueva. Mantener todo en `discount_tiers`.
- **Implementación:**
  1. Extender `validate_discount_tiers()` para aceptar `max_codes` opcional (default=None = ilimitado)
  2. Nuevo método `get_tier_pool_status(config_id, streak)` — cuenta códigos emitidos por tier
  3. En `generate_tiered_discount_code()`, verificar disponibilidad del tier específico antes de generar
  4. En `trivia_discount_service.py`/`game_service.py`, invocar `get_tier_pool_status()` y mostrar notificación si pool agotado
- **No crear nueva tabla `TierPool`:** Se reutiliza el patrón JSON existente en `discount_tiers`.

### Behavior When Tier Pool Exhausted

| Situación | Comportamiento |
|-----------|----------------|
| Usuario alcanza tier pero pool agotado | Silent skip en `generate_tiered_discount_code()`, retorna `None` |
| Handler recibe `None` | Muestra mensaje: "Este nivel de descuento está agotado, pero su racha continúa" |
| Racha del usuario | Se mantiene — puede seguir jugando para mantener streak |
| Codes_claimed global | NO se incrementa si no se generó código |

## Deferred Ideas

- **Stack de códigos por múltiples tiers:** No implementar ahora — usuario recibe solo el nivel más alto. Esta idea puede evaluarse en una fase futura si se desea.
- **Admin-configurable multi-code vs highest-only:** Deferido junto con la idea de stack.
- **Pool depletion ends promo early:** Opción de terminar promoción cuando TODOS los pools se agotan — no implementada inicialmente.
