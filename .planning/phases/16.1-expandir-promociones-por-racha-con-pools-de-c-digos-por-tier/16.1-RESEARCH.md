# Phase 16.1: Expandir Promociones por Racha con Pools de Códigos por Tier - Research

**Researched:** 2026-05-08
**Domain:** Promociones / Gamificación — sistema de pools de códigos de descuento por tier de racha
**Confidence:** HIGH

## Summary

Phase 16.1 extiende el sistema existente de `TriviaPromotionConfig` + `DiscountCode` para agregar pools de códigos por tier, cada uno con límite independiente. La implementación es estrictamente JSON: el campo `discount_tiers` se extiende in-place para incluir `max_codes` por cada tier. El comportamiento central es: cuando un usuario completa múltiples tiers, recibe SOLO el código del tier más alto que alcanza.

**Corrección clave del flujo de pool (不同于 CONTEXT.md):** El pool se agota cuando se **ISSUE/Genera** el código, no cuando el admin lo marca como USED. El campo `codes_claimed` existente en el modelo NO es el contador del pool — es un contador separado para tracking de redención. Phase 16.1 necesita agregar tracking de `codes_issued` por tier en el JSON de `discount_tiers`.

## User Constraints (from CONTEXT.md)

### Locked Decisions

- **Pool Structure:** Cada tier tiene su propio `max_codes` en `discount_tiers` JSON (no tabla nueva)
- **JSON extendida:** `[{"streak": 5, "discount": 50, "max_codes": 10}, ...]`
- **Solo más alto:** Usuario que completa tiers 5, 10, 15 recibe SOLO el de tier 15
- **Silent skip:** `generate_tiered_discount_code()` retorna `None` si pool agotado, no falla flujo
- **Pool depletion NO termina promoción:** Solo ese tier no genera más códigos
- **Códigos con expiración individual:** Cada código tiene su propia `generated_at + expiry_days`
- **Admin wizard:** Agregar paso de `max_codes` por tier en `trivia_discount_admin_handlers.py`

### Important Clarification (from User Input - 2026-05-08)

**El flujo de pool difiere de lo que sugiere el código existente:**

| Evento | ¿Afecta el pool? | Campo afectado |
|--------|-----------------|----------------|
| Usuario genera código (al alcanzar tier) | **SÍ** | `codes_issued` por tier en JSON |
| Admin marca código como USED | NO | `codes_claimed` global en config |
| Código expira o se cancela | NO | No afecta `codes_issued` (ya se emitió) |

**Semántica correcta:**
- `codes_issued` (en JSON por tier) = códigos generados/dispensados a usuarios
- `codes_claimed` (campo en TriviaPromotionConfig) = códigos marcados como USED por admin (solo para estadísticas)
- Pool depletion = `codes_issued >= max_codes` del tier
- Admin marcando código como USED NO afecta el pool (el pool ya se decrementó al issuance)

### Pattern 1: JSON Schema Extension (discount_tiers)

**What:** Extend `discount_tiers` JSON structure in-place, adding `max_codes` and `codes_issued` fields to each tier.

**When to use:** When pool limits need to be per-tier with issuance tracking.

**Example:**
```python
# Extended structure with max_codes and codes_issued tracking
[
  {"streak": 5, "discount": 50, "max_codes": 10, "codes_issued": 3},
  {"streak": 10, "discount": 75, "max_codes": 5, "codes_issued": 5},
  {"streak": 15, "discount": 100, "max_codes": 2, "codes_issued": 0}
]
```

**Note:** `codes_issued` starts at 0 and increments each time a code is generated for that tier.

### Pattern 2: Pool Status Query (Modified)

**What:** Count issued codes per tier by querying `DiscountCode` filtered by `discount_percentage` matching the tier's discount value. Alternative: track via `codes_issued` in JSON.

**When to use:** When pool depletion tracking is needed.

**Implementation (count query approach):**
```python
def get_tier_pool_status(self, config_id: int, streak: int) -> dict:
    """Count codes issued for a specific tier's discount percentage"""
    config = self.get_trivia_promotion_config(config_id)
    if not config:
        return {'codes_issued': 0, 'max_codes': None, 'available': True}

    tier = self.get_tier_for_streak(config, streak)
    if not tier:
        return {'codes_issued': 0, 'max_codes': None, 'available': True}

    max_codes = tier.get('max_codes')
    if max_codes is None:
        return {'codes_issued': 0, 'max_codes': None, 'available': True, 'unlimited': True}

    with SessionLocal() as session:
        codes_issued = session.query(DiscountCode).filter(
            DiscountCode.config_id == config_id,
            DiscountCode.discount_percentage == tier['discount']
        ).count()

    available = codes_issued < max_codes
    return {
        'codes_issued': codes_issued,
        'max_codes': max_codes,
        'available': available
    }
```

### Pattern 4: Admin Redemption Tracking (codes_claimed Separado)

**What:** `codes_claimed` field in `TriviaPromotionConfig` tracks admin redemptions SEPARATELY from pool depletion.

**When to use:** Always - this is the existing pattern that Phase 16.1 must preserve.

**Flow:**
- User generates code → `codes_issued` increments (pool depletion)
- Admin marks code as USED → `codes_claimed` increments (redemption tracking)
- These are independent counters with independent purposes

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Tier pool tracking | Separate `TierPool` table | JSON in `discount_tiers` + count query | CONTEXT.md explicitly forbids new table |
| Pool exhaustion handling | Throw exception | Return `None` + handler notification | Clean separation, non-blocking |
| Admin config | New table or column | Extend JSON wizard step | Minimal schema change |
| codes_issued counting | Assume codes_claimed is pool counter | Use count query by discount_percentage | User clarified codes_claimed tracks redemption, not issuance |

**Key insight:** The project has an existing pattern of using JSON columns for flexible configuration (`discount_tiers`). Phase 16.1 continues this pattern. The critical correction from user input is that `codes_claimed` (which only increments on admin redemption) is NOT the pool counter — pool depletion happens at code issuance time.

## Common Pitfalls

### Pitfall 1: Conflating codes_claimed with Pool Counter
**What goes wrong:** Using `max_codes - codes_claimed` to check pool availability.
**Why it happens:** Existing code does this, but `codes_claimed` only increments when admin marks code as USED.
**How to avoid:** Use count query on `DiscountCode` filtered by `config_id` AND `discount_percentage`, OR maintain `codes_issued` in JSON.
**Warning signs:** Code at `trivia_discount_service.py:358` and `:607` uses wrong formula.

### Pitfall 2: Race Condition on Pool Depletion
**What goes wrong:** Two users reach tier simultaneously, both see available, both generate code (over-issuance).
**Why it happens:** No locking between pool check and code generation.
**How to avoid:** Use `SELECT FOR UPDATE` on config row OR accept eventual consistency (over-issuance by 1-2 is acceptable given small pool sizes).
**Warning signs:** `codes_issued > max_codes` in stats.

### Pitfall 3: Admin Wizard JSON Input
**What goes wrong:** Admin enters invalid JSON or invalid `max_codes` values.
**Why it happens:** No frontend validation before submission.
**How to avoid:** Extend `validate_discount_tiers()` to validate `max_codes` field, return clear error message.

```python
def get_available_codes_count(self, config_id: int, streak_tier: int = None) -> int:
    """Obtiene cantidad de códigos disponibles para un tier específico."""
    config = self.get_trivia_promotion_config(config_id)
    if not config:
        return 0

    if streak_tier is None:
        # Fallback al método antiguo (sin tiers)
        return max(0, config.max_codes - config.codes_claimed)

    # Para tier específico: contar códigos emitidos con ese discount_percentage
    tier_pool = self.get_tier_pool_status(config_id, streak_tier)
    if tier_pool.get('unlimited'):
        return float('inf')
    return max(0, tier_pool['max_codes'] - tier_pool['codes_issued'])
```

### Extend validate_discount_tiers (in trivia_discount_service.py)

```python
def validate_discount_tiers(self, tiers: List[dict]) -> tuple[bool, str]:
    """Valida estructura de tiers. Extendido para max_codes opcional."""
    if not tiers:
        return False, "La lista de tiers no puede estar vacía"

    if len(tiers) > 5:
        return False, "Máximo 5 tiers permitidos"

    prev_streak = 0
    prev_discount = 0

    for i, tier in enumerate(tiers):
        if 'streak' not in tier or 'discount' not in tier:
            return False, f"Tier {i+1} debe tener 'streak' y 'discount'"

        streak = tier['streak']
        discount = tier['discount']
        max_codes = tier.get('max_codes')  # NEW: optional

        if not isinstance(streak, int) or streak < 1:
            return False, f"Tier {i+1}: streak debe ser entero positivo"

        if not isinstance(discount, int) or discount < 0 or discount > 100:
            return False, f"Tier {i+1}: discount debe ser 0-100"

        # NEW: validate max_codes if present
        if max_codes is not None:
            if not isinstance(max_codes, int) or max_codes < 0:
                return False, f"Tier {i+1}: max_codes debe ser entero >= 0"

        if streak <= prev_streak:
            return False, f"Tier {i+1}: streak debe ser mayor que el anterior ({prev_streak})"

        if discount <= prev_discount:
            return False, f"Tier {i+1}: discount debe ser mayor que el anterior ({prev_discount})"

        prev_streak = streak
        prev_discount = discount

    return True, ""
```

### Modify generate_tiered_discount_code (in trivia_discount_service.py)

```python
def generate_tiered_discount_code(
    self,
    user_id: int,
    config_id: int,
    discount_percentage: int,
    streak_tier: int,
    username: Optional[str] = None,
    first_name: Optional[str] = None
) -> Optional[dict]:
    """
    Genera código de descuento para un tier específico.
    Retorna None si el pool del tier está agotado.
    """
    with SessionLocal() as session:
        try:
            config = session.get(TriviaPromotionConfig, config_id)
            if not config or config.status != 'active':
                return None

            # Verificar vigencia
            now = datetime.utcnow()
            if config.start_date and now < config.start_date:
                return None
            if config.end_date and now > config.end_date:
                return None

            # Verificar duración relativa
            if config.duration_minutes and config.started_at:
                remaining = self.get_time_remaining(config_id)
                if remaining <= 0:
                    return None

            # NUEVO: Verificar pool del tier ANTES de generar
            tier_pool = self.get_tier_pool_status(config_id, streak_tier)
            if not tier_pool['available']:
                logger.info(f"Pool exhausted for tier {streak_tier}")
                return None  # Silent skip

            # Verificar que usuario no tenga ya código activo
            existing = session.query(DiscountCode).filter(
                DiscountCode.user_id == user_id,
                DiscountCode.config_id == config_id,
                DiscountCode.status == DiscountCodeStatus.ACTIVE
            ).first()
            if existing:
                return None

            # Generar código único
            code = _generate_trivia_code()

            discount_code = DiscountCode(
                config_id=config_id,
                code=code,
                user_id=user_id,
                username=username,
                first_name=first_name,
                promotion_id=config.promotion_id,
                status=DiscountCodeStatus.ACTIVE,
                discount_percentage=discount_percentage
            )
            session.add(discount_code)
            session.commit()
            session.refresh(discount_code)

            result = {
                'code': discount_code.code,
                'promotion_name': config.promotion.name if config.promotion else config.custom_description,
                'discount_percentage': discount_percentage
            }
            logger.info(f"generate_tiered_discount_code - {user_id} - success: {code} at {discount_percentage}%")
            return result
        except Exception as e:
            session.rollback()
            logger.error(f"generate_tiered_discount_code - {user_id} - error: {e}")
            return None
```
